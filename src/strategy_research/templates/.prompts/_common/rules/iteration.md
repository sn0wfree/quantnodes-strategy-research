# 小步迭代原则 + 执行前自检

> 适用于所有涉及"修改 → 验证 → 评估"循环的任务。修复 bug、优化参数、调整策略都属于此范畴。

## 小步迭代原则

### 每次只改一处

**核心约束**：一次改动**只能引入一个变量**。

```python
# ✅ 正确：只改 top_n
PARAMS = {"top_n": 20, ...}  # 原 10

# ❌ 错误：同时改 top_n + max_weight
PARAMS = {"top_n": 20, "max_weight": 0.3, ...}  # 改了两个
```

**原因**：一次改多个变量，无法归因改善/退化来自哪个。

### 修改 → 验证 → 评估 循环

```
修改 1 处
   ↓
跑回测 / 评估影响
   ↓
改善？ → 保留，进入下一轮
退化？ → 回滚，停止
不变？ → 标记（可能与其他改动协同）
```

### 修复问题时精确修复，不重写

```python
# ✅ 正确：只修 bug 部分
def calculate_signal(data):
    if data.empty:  # 新增的空检查
        return pd.Series()
    return ts_return(data['close'], 20)

# ❌ 错误：重写整个函数
def calculate_signal(data):
    # 重写逻辑...
```

### 修复/优化尝试设上限（默认 3 轮）

**避免无意义打转**：

- 3 轮修复无改善 → 停止，换思路
- 5 轮参数优化无提升 → 停止，回滚到基线
- 持续失败 → 报告用户，请求指导

## 执行前自检（每次回复前过一遍）

### 自检清单

- [ ] 涉及回测时，是否走到步骤 3（run_backtest）？没有 → 用"诚实模板"开头
- [ ] 数字是否都有 `[来源: ...]` 或 `[未验证]` 标记？
- [ ] 回测结论是否带了 `run_id`？
- [ ] 对比表是否区分了"已测"vs"未测"？
- [ ] 当前模式是 chat 还是 role？输出形态匹配吗？（参考 principles.md "受众区分"）

### 自检示例

#### ✅ 正确示例 1：诚实承认没数据

**场景**：用户问"V1 的 sharpe 多少？"

**自检**：

- [ ] 涉及回测吗？是
- [ ] 我调用 run_backtest 了吗？❌ 没有
- [ ] → 触发"诚实模板"

**输出**：

> "我没调用 `run_backtest`，无法给出 sharpe。需要先确认 V1 策略文件存在，再运行回测。"

#### ✅ 正确示例 2：诚实承认没数据，不输出对比表

**场景**：用户问"对比 V1 和 V2 哪个好？"

**自检**：

- [ ] 涉及回测吗？是
- [ ] 我有 V1 和 V2 的回测数据吗？❌ 没有
- [ ] 对比表区分"已测"vs"未测"了吗？→ 不输出对比表
- [ ] → 触发"诚实模板"

**输出**：

> "我没跑过 V1 和 V2 的回测。需要先创建两个策略并跑回测才能对比。"

#### ✅ 正确示例 3：诚实标注未验证

**场景**：用户问"V2 比 V1 好吗？"，我刚跑过 V1 但没跑 V2

**自检**：

- [ ] 我有 V2 数据吗？❌ 没有
- [ ] 我有 V1 数据吗？✅ 有
- [ ] → 不能直接对比，但可以汇报 V1 的数据

**输出**：

> "V1 数据（已跑，run_id=xxx）：sharpe 1.42, 年化 18.5%
> V2 数据：未跑 `[未验证]`
>
> 要对比 V1 和 V2，需要先跑 V2 的回测。"

#### ❌ 错误示例 1：编造 V2 数据

**场景**：同上

**错误输出**：

> ❌ "V1 sharpe 1.42，V2 sharpe 1.85，V2 更好。"

（V2 数据从哪来？**编造**）

#### ❌ 错误示例 2：跳过 run_backtest 推算

**场景**：用户问"V1 的年化是多少？"

**错误输出**：

> ❌ "V1 的年化大约是 15% 左右。"

（"大约"是推测，没有 tool 返回值 = 编造）

## 何时读本文件

- 进入修复/优化迭代流程
- 多次尝试后仍无改善
- 准备做参数优化
- 不确定"每次只改一处"的边界

## 何时**不**读本文件

- 简单问题，chat.md 内联规则已够
- 单次性操作（不涉及迭代）
- 你在多次对话中已熟练应用小步迭代
