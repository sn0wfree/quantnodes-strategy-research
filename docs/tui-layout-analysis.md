# TUI 布局结构深度分析

**日期**: 2026-07-26
**聚焦**: 各项目 TUI 的布局结构优劣对比

---

## 一、五种布局模式

### 1. vibe-trading — 顺序流布局

```
┌─────────────────────────────────────────┐
│ Banner (ASCII logo)                     │
├─────────────────────────────────────────┤
│ [Rich.Live 瞬态仪表盘]                  │
│  ● Tool call 1                          │
│  ● Tool call 2                          │
├─────────────────────────────────────────┤
│ Static tool lines (持久)                │
│  ● Market Data ("AAPL")      1.4s       │
│  ● Backtest (strategy.py)    3.2s       │
├─────────────────────────────────────────┤
│ Answer (Markdown 渲染)                  │
│ 策略名称: 均值回归策略                   │
│ 年化收益: 12.3%                         │
├─────────────────────────────────────────┤
│ Footer: /show run_001 · 3 tools · 4.1s  │
├─────────────────────────────────────────┤
│ > Type /help, then Enter...             │
└─────────────────────────────────────────┘
```

**特点**:
- 无固定面板，所有内容顺序排列
- 工具调用用 `Rich.Live` 瞬态显示（执行完消失）
- 静态工具行持久保留
- 答案用 Markdown 渲染

**优势**:
- 信息密度高（无面板边框浪费空间）
- 简单直观（像终端一样滚动）
- 工具调用不占固定空间

**劣势**:
- 历史记录被新内容挤出屏幕
- 无法同时看多个信息源
- 长对话时工具调用信息丢失

### 2. Claude Code — 单栏滚动布局

```
┌─────────────────────────────────────────┐
│ Claude Code v1.0.0 · claude-3-opus      │
│ ~/Projects/my-app                       │
├─────────────────────────────────────────┤
│ > 帮我修复这个 bug                       │
│                                         │
│ 我来分析一下这个问题...                  │
│                                         │
│ ┌─ Bash ──────────────────────────────┐ │
│ │ $ npm test                           │ │
│ │ FAIL src/app.test.ts                 │ │
│ │   Expected: 200, Received: 500       │ │
│ └─────────────────────────────────────┘ │
│                                         │
│ 找到了问题：API 返回 500 错误。          │
│ 修复方案：...                           │
│                                         │
│ ┌─ Edit ──────────────────────────────┐ │
│ │ --- a/src/app.ts                     │ │
│ │ +++ b/src/app.ts                     │ │
│ │ @@ -10, +10 @@                      │ │
│ │ - return res.status(500).send(err)  │ │
│ │ + return res.status(200).send(data)  │ │
│ └─────────────────────────────────────┘ │
│                                         │
│ 已修复。运行 npm test 验证。             │
├─────────────────────────────────────────┤
│ > _                                     │
└─────────────────────────────────────────┘
```

**特点**:
- 单栏，所有内容顺序排列
- 工具调用用内联框显示（Bash/Edit/Read）
- Diff 用语法高亮渲染
- 权限提示内联显示

**优势**:
- 极简设计，无学习成本
- 工具输出内联，上下文完整
- Diff 渲染清晰

**劣势**:
- 无侧边栏（看不到文件树）
- 无活动轨（工具调用状态不直观）
- 长对话时历史被挤出

### 3. Codex — 单栏滚动布局（类似 Claude Code）

```
┌─────────────────────────────────────────┐
│ Codex                                   │
├─────────────────────────────────────────┤
│ > 分析这个代码库                         │
│                                         │
│ 我来分析一下...                          │
│                                         │
│ [Tool: read_file]                       │
│ Reading src/main.py...                  │
│                                         │
│ [Tool: run_bash]                        │
│ $ python -m pytest                      │
│ 15 passed, 0 failed                    │
│                                         │
│ 分析结果：...                           │
├─────────────────────────────────────────┤
│ > _                                     │
└─────────────────────────────────────────┘
```

**特点**:
- 与 Claude Code 类似的单栏布局
- 工具调用用 `[Tool: name]` 标记
- 更简单的工具输出渲染

**优势**:
- 简单直接
- 与 ChatGPT 界面风格一致

**劣势**:
- 工具调用不够直观
- 无活动状态显示

### 4. OpenCode — 多栏 + 命令面板布局

```
┌─────────────────────────────────────────────────────────────────────┐
│ OpenCode                                    Plan Mode    v0.5.0   │
├──────────┬──────────────────────────────────────┬──────────────────┤
│ Sessions │ Transcript                           │ Models           │
│          │                                      │                  │
│ > session│ > 帮我分析一下均值回归策略            │ gpt-4o     ●    │
│   15:30  │                                     │ claude-3   ○    │
│   14:20  │ 我来分析一下...                       │ deepseek   ○    │
│   13:10  │                                     │                  │
│          │ [Tool: read_file]                    │ Agents           │
│          │ Reading config.yaml...               │                  │
│          │                                     │ researcher  ●    │
│          │ [Tool: run_backtest]                 │ strategist  ○    │
│          │ Running strategy.py...               │ critic      ○    │
│          │                                     │                  │
│          │ 分析结果：...                         │ Skills           │
│          │                                     │                  │
│          │                                     │ backtest    ○    │
│          │                                     │ analysis    ○    │
├──────────┴──────────────────────────────────────┴──────────────────┤
│ ▸ 帮我分析一下均值回归策略在沪深300上的表现                        │
├─────────────────────────────────────────────────────────────────────┤
│ F1 Help  Ctrl+C Halt  Ctrl+D Quit  Ctrl+L Clear  Tab Switch Mode  │
└─────────────────────────────────────────────────────────────────────┘
```

**特点**:
- 多栏布局：侧边栏 + 对话 + 右侧面板
- 右侧面板可切换：Models / Agents / Skills / Files
- 命令面板 (Ctrl+P) 模糊搜索
- 状态栏显示模式/模型/版本

**优势**:
- 信息密度高（同时看多个信息源）
- 右侧面板灵活（可切换内容）
- 命令面板快速访问功能

**劣势**:
- 空间占用大（三栏各占宽度）
- 复杂度高（需要学习）
- 小屏幕体验差

### 5. 本项目 — 三栏固定布局

```
┌─────────────────────────────────────────────────────────────────────┐
│ QuantNodes Strategy-Research                            v0.5.0  🟢 │
├──────────┬──────────────────────────────────────┬──────────────────┤

│ /history │                                      │                  │
│ /goal    │ ─────────────────────────────────    │ ● run_backtest   │
│ /search  │ 你: 帮我分析一下均值回归策略在     │   strategy.py    │
│ /swarm   │ 沪深300上的表现                      │   ⏳ 12.4s       │
│ /skill   │                                      │                  │
│ /show    │ ─────────────────────────────────    │ ● get_market_data│
│ /clear   │ 🤖 thinking... (2.3s)               │   daily_ohlcv    │

│ /shadow  │ (Mean Reversion)                     │ ─────────────── │
│ /export  │ 标的: 沪深300指数                     │ ● factor_analysis│
│ /debug   │                                      │   momentum       │
│ /halt    │ 关键指标:                            │   ✔ 1.2s         │
│ /resume  │ - 年化收益: 12.3%                    │                  │
│ /quit    │ - 最大回撤: -8.5%                    │ ⏳ 累计 14.7s    │
│          │ - 夏普比率: 1.42                     │ 3 tools · 1.2k   │
│          │ - 胜率: 58.2%                        │ tokens · $0.003  │
├──────────┴──────────────────────────────────────┴──────────────────┤
│ ▸ 帮我分析一下均值回归策略在沪深300上的表现                        │
├─────────────────────────────────────────────────────────────────────┤
│ F1 Help  Ctrl+C Halt  Ctrl+D Quit  Ctrl+L Clear  Tab Switch Mode  │
└─────────────────────────────────────────────────────────────────────┘
```

**特点**:
- 三栏固定：侧边栏(26col) + 对话(1fr) + 活动轨(36col)
- 侧边栏显示可点击的 slash 命令
- 活动轨显示工具调用状态
- 底部输入框 + 状态栏

**优势**:
- 信息密度高（三栏并行）
- 工具调用状态实时可见
- 命令快速访问

**劣势**:
- 空间占用大（三栏各占宽度）
- 侧边栏功能单一（只有命令列表）
- 活动轨内容单一（只有工具调用）

## 二、布局优劣对比矩阵

| 维度 | vibe-trading | Claude Code | Codex | OpenCode | 本项目 |
|---|---|---|---|---|---|
| **信息密度** | 高（无面板浪费） | 中（单栏） | 低（单栏简单） | 高（多栏） | 高（三栏） |
| **上下文保持** | 低（历史被挤出） | 低（单栏滚动） | 低（单栏滚动） | 中（侧边栏保留） | 中（活动轨保留） |
| **学习成本** | 低（终端风格） | 低（极简） | 低（极简） | 高（多栏+命令面板） | 中（三栏） |
| **小屏幕体验** | 好（自适应） | 好（自适应） | 好（自适应） | 差（三栏挤） | 差（三栏挤） |
| **工具调用可见性** | 中（瞬态显示） | 高（内联框） | 低（文本标记） | 高（内联+状态） | 高（活动轨） |
| **命令访问** | 高（模糊补全） | 高（slash命令） | 中（基础slash） | 很高（命令面板） | 中（点击侧边栏） |
| **可扩展性** | 低（顺序流） | 低（单栏） | 低（单栏） | 高（多栏可切换） | 中（三栏固定） |

## 三、可借鉴的布局元素

### 1. 从 vibe-trading 借鉴

**借鉴**: 瞬态活动仪表盘

```
当前: 活动轨是固定面板，始终显示
改进: 工具调用时瞬态显示，完成后消失或折叠
```

**理由**:
- 工具调用是临时信息，不需要始终显示
- 释放空间给对话内容
- 执行完后可折叠为一行摘要

**实现**: 用 `Rich.Live` 或 Textual `Rule` + 折叠逻辑

---

### 2. 从 Claude Code 借鉴

**借鉴**: 工具调用内联框

```
当前: 活动轨显示 "● read_file config.yaml ✔ 0.3s"
改进: 对话内显示内联框
```

```
┌─ read_file ──────────────────────────────┐
│ config.yaml                              │
│                                          │
│ provider: minimax                        │
│ model: MiniMax-M3                        │
│ api_key: env:LLM_API_KEY                 │
└──────────────────────────────────────────┘
```

**理由**:
- 工具输出与对话上下文在一起
- 更容易理解工具调用的结果
- Diff/文件内容可直接在对话中查看

**实现**: Textual `Static` widget + Rich 渲染

---

### 3. 从 OpenCode 借鉴

**借鉴**: 右侧面板可切换

```
当前: 活动轨固定显示工具调用
改进: 右侧面板可切换内容
```

```
┌──────────────────────────────────────────┐
│ Activity  [Models] [Files] [Skills]      │  ← 标签切换

│ 或                                       │
├──────────────────────────────────────────┤
│ gpt-4o     ●                             │  ← Models 视图
│ claude-3   ○                             │

├──────────────────────────────────────────┤
```

**理由**:
- 活动轨空间有限，可切换显示不同内容
- Models/Files/Skills 视图对量化研究有用

### 4. 从 Claude Code 借鉴

**借鉴**: 权限提示内联

```
当前: 工具调用直接执行
改进: 危险操作前内联提示
```

```
┌─ run_bash ───────────────────────────────┐
│ $ rm -rf /tmp/test_data                  │
│                                          │
│ ⚠ This will delete files. Allow? [Y/n]  │

```

**理由**:
- 安全性（防止误操作）
- 用户知情权
- 与 Claude Code 的 5 级权限模式对齐

**实现**: Textual `Prompt` 或自定义 modal

---

### 5. 从 OpenCode 借鉴

**借鉴**: 状态栏信息丰富

```
当前: HintFooter 只显示快捷键
改进: 状态栏显示更多信息
```

```
┌─────────────────────────────────────────────────────────────────────┐
│ F1 Help  Ctrl+C Halt  Ctrl+D Quit  │ minimax/MiniMax-M3  │ Plan  │
└─────────────────────────────────────────────────────────────────────┘
```

**理由**:
- 用户随时知道当前模型/模式
- 减少认知负担
- 与 OpenCode 的状态栏对齐

**实现**: 扩展 `HintFooter` widget

## 六、推荐

**推荐方案 A（增强三栏）**，理由:
1. 改动最小（基于现有布局）
2. 保留三栏信息密度优势
3. 右侧面板标签切换增加灵活性
4. 工具调用内联提升可读性
5. 状态栏信息丰富
