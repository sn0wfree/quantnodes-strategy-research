# L7 v0.3 — Hook 触发迁移到 Step

> **Status:** Draft (branch `l7-v0.3-hook-migration`)
> **承接:** L7 v0.2 完成 4 个决策点迁移。本步把部分 Hook 触发从
> `_run_loop_core` 骨架移入 Step 内部（方案 1：Step 自触发）。

## 目标

让 Step 自触发与自身生命周期相关的 Hook，`_run_loop_core` 骨架只保留
**跨 Step 的轮次级** Hook。这样自定义 Step 可以在行为差异的同时
精确控制"何时触发哪个 Hook"。

## 迁移映射

| Hook 事件 | 当前位置 | v0.3 迁移到 | 触发时机 |
|-----------|----------|------------|----------|
| `before_run` | `_run_loop_core` L1140 | **保留骨架** | 循环前一次（跨 Step，不动） |
| `before_iteration` | L1152 | `LLMCallStep.execute` 开头 | LLM 调用前 |
| `on_error` | L1169 | `LLMCallStep.execute` 错误路径 | LLM 调用失败 |
| `after_iteration` | L1194/1197/1209/1222 | **保留骨架** | 轮次结束（跨 Step，不动） |
| `before_execute_tools` | L1212 | `ToolExecutionStep.execute` 开头 | 工具执行前 |
| `after_tool_executed` / `on_tool_error` | L1313/1315 | `ToolExecutionStep.execute` 内部 | 每个工具结果后 |
| `after_run` | L1244/1251 | `FinalizationStep.execute` | 循环结束后 |

## 关键约束

1. **触发顺序和次数必须与现状完全一致**（现有 hook 测试 = 等价 oracle）
2. **`after_iteration` 保留在骨架**——它跨 stop / breaker / 工具三个路径，
   语义是"轮次结束"信号，不属于任何单个 Step
3. **`before_run` / `after_run` 保留骨架**——它们是 run 级生命周期，
   Step 不应重放

## 实现细节

### LLMCallStep.execute 增加 before_iteration + on_error

```python
class DefaultLLMCallStep:
    async def execute(self, ctx, *, async_mode):
        loop = self._loop
        # before_iteration hook（LLM 调用前）
        await loop._afire_hooks("before_iteration", ctx.hook_ctx)
        # ... 现有 _get_response 调用 ...
        except LLMError as exc:
            loop._handle_llm_error(exc, ctx.iteration, ctx.result)
            await loop._afire_hooks("on_error", ctx.hook_ctx, exc)
            ctx.should_stop = True
            ctx.stop_reason = "error"
            return ctx
```

### ToolExecutionStep.execute 增加 before_execute_tools + per-tool hooks

```python
class DefaultToolExecutionStep:
    async def execute(self, ctx, *, async_mode):
        loop = self._loop
        await loop._afire_hooks("before_execute_tools", ctx.hook_ctx)
        if async_mode:
            tool_result_msgs = await loop._aexecute_tool_batch(ctx.response.tool_calls, ctx.result)
        else:
            tool_result_msgs = loop._execute_tool_batch(ctx.response.tool_calls, ctx.result)
        # per-tool hooks
        for tc, msg in zip(ctx.response.tool_calls, tool_result_msgs):
            is_err = isinstance(msg.get("content"), str) and msg["content"].startswith('{"status": "error"')
            if is_err:
                await loop._afire_hooks("on_tool_error", ctx.hook_ctx, tc, RuntimeError(msg["content"]))
            else:
                await loop._afire_hooks("after_tool_executed", ctx.hook_ctx, tc, msg)
        return ctx
```

### FinalizationStep.execute 增加 after_run

```python
class DefaultFinalizationStep:
    async def execute(self, ctx, *, async_mode):
        loop = self._loop
        # metrics + claim validation 已有 loop 处理，这里只触发 hook
        await loop._afire_hooks("after_run", ctx.hook_ctx, ctx.result)
        return ctx
```

## 骨架保留的 Hook

```python
# 骨架仍直接调用（跨 Step）
await _fire("before_run", hook_ctx)          # 循环前
await _fire("after_iteration", hook_ctx)     # 每轮结束（3 个位置）
```

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| Hook 触发顺序变化破坏 hook 测试 | 严格按迁移映射；迁移后跑全部 hook 相关测试 |
| `_run_loop_core` 中已删的 hook 被遗漏 | 迁移后 grep 确认无 `_fire("before_execute_tools")` 等残留 |
| sync/async 双路径 hook 触发不一致 | Step 内 `_afire_hooks`（async）；sync 桥 `_fire_hooks` 已有 |
| `LLMCallStep` 迁移后 on_error 重复 | 骨架删除 L1169 的 `on_error`，Step 内新增 |
