对照讨论锚点

  1. 编排层的 AgentLoop 是不是唯一该装 ContextHub 的地方？
    图上 ContextHub 从右侧直接连进 AgentLoop。但 study/swarm/workflow 三套编排是否也各需要一个「自己的组装点」？若共用一个 Hub，角色 prompt 与工具集会不会被跨编排污染？
  2. 能力层与数据层要不要都挂到 Registry？
    图中 Registry 只连到能力层（解析供给）。数据层 11 个 store 目前是具体类、不经注册。若它们也进 Registry，契约（真源/写入者/生命周期）由谁定义？
  3. InvariantLayer 只画了一条虚线到「数据层」，够吗？
    它实际要守护的是编排层的预算/停止条件（不变量在代码里，不在数据层）。虚线是否应改为直接指向 AgentLoop 与 StudyRunner？
  4. 统一快照放在最右下，是否应上移成 ContextHub 的一部分？
    快照是 ContextHub 的产物（explain/snapshot），画成并列的第四个中枢会让人误以为是独立系统。
  5. 能力层的 skills 与 injectors 合并在一格，是否该拆？
    skills 是「文档型能力」，injectors 是「上下文贡献方」，语义不同。Tier 1（RSI 基因组）只动 skills/injectors 里的 .prompts/.skills，与 Tier 2 的工作区工件要分开画吗？
  6. 横切层（evals / 不变量 / CI）没有画进主栈
    因为它们跨层。但「不变量层」在右脊、「评测」在图外——是否该在主栈底部加一条横切带，把 eval 跟幅、conformance、CI 门禁、holdout 都列出来？
  7. 四张问题编号该挪到哪？
    ① 反向依赖（图上标在 langgraph 附近，实际有 3 处）② SSE 双轨 ③ 持久化无契约 ④ 上下文无仲裁 ⑤ 记忆断裂 ⑥ 导演层缺失 —— 位置对吗？
