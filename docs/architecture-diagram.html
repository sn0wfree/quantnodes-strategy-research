渠道 → 平台（虚线框：Gateway · 执行面 · 平台数据） → 研究域（IP · 单独一层）。平台业务无关，研究域只填内容不开旁路；每个格只有一个 owner，每个箭头写着传递的是什么。

Gateway 内核（唯一控制面） 模块 / 执行面 / 数据 协议 / 研究域（护城河） 待建（Director / RunContext / InvariantLayer / 工件登记·身份） 蓝箭头 ＝ 管线（WorkRequest → mailbox → admission → runtime → 产物 → 持久化）

图上标注速查

术语一句话说明
T1 / T2 / T3 执行三层T1 协程＝进程内 asyncio，跑等 LLM 的轻活（llm/react 节点）；T2 进程＝常驻子进程池，跑烧 CPU 的重活（真并行·崩溃隔离·可硬杀——GIL 排除线程/协程）；T3 沙箱＝OS 级隔离跑不可信代码（Windows 暂无业界方案，占位）
turn / runturn＝会话中被准入的一次执行权（串行单位，并行全在 turn 内）；run＝一次执行实例，子 run 挂在根 run 成树
mailbox会话内的等待队列——所有排队都发生在这，闸不排队
steer / followup / interrupt插话注入当前 run（安全点、只追加）/ 排队等下一 turn / 打断当前 turn（级联取消整棵子 run 树）
lane（通道）同 key 请求的专用串行道：session lane 保 turn 顺序；subagent:{session} 子代理通道（默认并发 8，不碰 mailbox 防自锁）
cap 20 · 溢出 summarizemailbox 深度上限；满了把最旧的等待消息摘要化——全系统唯一拒绝点
优先级老化高优先级只能领先有限时间（~15s 量级），之后不得继续插队——防 automation 饿死用户消息
容量组闸每类活的最大并发槽位（chat 宽 / study 窄=executor 池上限 / cron 隔离）；满→排队不拒绝，running 不抢占
fence（栅栏）写权限认领（activeRunId）+ 提交校验：被取代/被取消的 run 陈旧产物不落库
fold 重建重启后从事件流重放算出状态（恢复状态，不恢复执行——被打断的 run 标 interrupted，重试靠重提）
grace关闭时给运行中 turn 的收尾宽限（默认 ~5 分钟，可配置），超时标 interrupted
Preset / 节点类型图＝执行的形状数据（chat=单节点退化图 / research=方法论图Tier 0 冻结 / fanout·dag=Tier 1 可提案）；节点＝图上一步（llm/react/cpu/graph，每阶段可开关 ReAct）
Tier 0 / 1 / 2（基因组）冻结不可改（预算/停止/状态机/方法论）/ 提案可进化（prompt/skill/图形状）/ 研究产物可自改（strategy.py）
home_session_key研究实体的固定会话——所有 round 都回这排队：同一研究永不并行，人工与 scheduler 可接力
EventStore唯一事实源：一切进展写成事件（含流式 delta，永不清理＝完整回放素材）；每 session 一个自包含 SQLite（event+blobs+message+goal/todo）；回执只说收下/拒了，其余看事件流
ExecutorBridgeGateway 内把 cpu 节点派发给子进程池的桥：dispatch/events/cancel/heartbeat 四通道
ConfigHub配置中心：平台所有组件参数唯一来源——分层装载（代码默认<文件<环境变量）、治理分级（运维可调/Tier1 提案/敏感隔离）、启动校验 fail-fast、脱敏指纹进事件流
RuntimeHub解析每个 turn 的执行体配置（preset 图 + provider/模型绑定）；provider client 层自带 RPM/TPM 限流（超限排队不拒绝）
ContextHub每次模型调用前装配上下文的唯一所有者（=OpenClaw Prompt Assembly）：collect→arbitrate→render
RunContext单次 run 的约束包（预算快照/事件出口/取消/追踪/注入通道）——回答「在什么约束下跑」
