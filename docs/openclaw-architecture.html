3 · 差异分析（按修的杠杆排序）

序差距OpenClaw 怎么做我们怎么改估工
1模型循环不可换harness 插件 + 选择序 + 声明式回退定义 AgentRuntime（prepare/run/settle）+ 选择器；role_factory / chat_loop 收成两个实现（不合并）2d
2控制面 3–4 套Gateway 一个；Session Controller 一个 owner收敛为 1 控制面 + N runtime：SessionController 状态机 + 队列模式 + Director 策略；StudyLoop 降为 research runtime3–4d
3无 write fenceactiveWriterRunId + 提交事务校验run 级 activeRunId + 提交校验：被取代的 run 不能提交陈旧数据1d
4无缓存边界/预算归属稳定段在上、目录在下；谁产出谁拥有ContextHub 扩两条：缓存前缀稳定 + 分层预算（per-attempt/provider/idle/总）2d
5协议无版本compat.pluginApi / minHostVersion；不匹配即拒绝给 29 个协议加 PROTOCOL_VERSION + 不匹配拒绝（不降级）；CI 门禁同步1d
6状态表达单一6 个正交真值（owned/admissible/active/injectable/abortable/settled）RunStatus 从单一 state 改为 6 个正交维度0.5d
7记忆无清除边界可归因清除 + 明示「删除不覆盖什么」自主研究会产生大量记忆：补 retention/purge 语义1d

4 · 一句话

我们不缺功能，缺的是 OpenClaw 那种「一个 owner 对一件事」的纪律：控制面 3–4 套、执行面混层、协议无版本、run 无栅栏、prompt 无缓存边界。 补这 5 条，架构会立刻「正」起来；研究方向、claims、AEGIS、两阶段 journal、70 题 golden 门禁——这些我们的护城河，业界无对标物，一点都不用动。
