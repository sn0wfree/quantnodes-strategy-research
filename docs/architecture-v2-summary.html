3 · 三层接缝规范 统一的是「合格标准」，不是协议数量

L1 窄协议
已有 29 个复用 + 只补 3 个
EventSource · ToolsetProvider · PersistenceContract
规则：3–5 方法 · Protocol 不用 ABC · 无状态优先 · 结构化数据进出 · 协议间不互相依赖
L2 统一注册
扩展 core/registry.py：能力标签 / 依赖闭包 / validate / describe
5 套注册表 → 1 主 + N 薄适配；对外 API 不变；不新建平行注册表
L3 一致性套件
每协议一套可运行 pytest：实现 = 写类 + 跑套件
接入成本目标：1 文件 + 1 行 + 1 套件（当前：store 类部件需「读源码模仿约定」）

4 · 三层基因组（RSI） 只改行为工件，不改不变量

Tier 0 · 冻结 agent 无权触碰

预算 · 停止条件 · 状态机 · scope 隔离

由 InvariantLayer 守护 —— 「错了就错」的东西不做成插件（DSH 自己也放独立不变量层）

Tier 1 · 提案制 真正的 RSI

角色提示 .prompts · 技能 .skills · 工具集组合

agent 只提案 → golden + holdout + 不变量 三重门禁 → CI/人审晋级 → git 秒级回滚

现状：这些在包内，agent 写不到（workspace_setup 明确排除）→ 需提案通道

Tier 2 · 可自改 今天已在发生

strategy.py · config · notes · 因子代码

但这是「研究产出」，不是「自我进化」—— 区别在于 Tier 1 改的是系统自己的行为定义

突变 → 晋级 → 回滚

① 突变：agent 提案 Tier1 改动→ ② 评审：单测 + conformance + golden + holdout + 不变量→ ③ 晋级：CI/人审合并→ ④ 观察期 nightly + AEGIS→ ⑤ 退化则 git revert（秒级）

硬规则：只能提案不能自批 · 违反不变量 = 直接判负 · Tier 0 永不入 genome · 晋级记入 event log
