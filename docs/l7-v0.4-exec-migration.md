# L7 v0.4 — LLM 调用 + 终化执行迁移到 Step

> **Status:** Draft (branch `l7-v0.4-exec-migration`)
> **承接:** L7 v0.3 完成 ToolExecutionStep 执行迁移 + hook 自触发。本步把
> LLM 调用（LLMCallStep）与终化（FinalizationStep）的执行也迁入 Step。

## 目标

完成 `_run_loop_core` 的"执行迁移"收尾：

| Step | 执行迁移 | hook 自触发 |
|------|---------|-------------|
| **LLMCallStep** | 真正驱动 `_get_response`（await） | `before_iteration` + `on_error` |
| **FinalizationStep** | 真正驱动 metrics + claim validation | `after_run`（正常结束路径） |

## 关键难点与决策

### 难点 1：`_get_response` 是 async def

`DefaultLLMCallStep.execute` 当前是 sync def 且未 await（v0.1 stub 遗留 bug）。
v0.4 改为 `async def execute` + `await self._loop._get_response(...)`。
`_run_loop_core` 已用 `_call_step`（会 `inspect.isawaitable` 处理），无需改。

### 难点 2：`before_iteration` 触发时机

骨架 L1152 在 `_get_response` 之前触发 `before_iteration`。迁移后：
- LLMCallStep.execute 开头触发 `before_iteration`
- 骨架删除 L1152

### 难点 3：`on_error` 触发时机

骨架 L1169 在 `_handle_llm_error` 后触发 `on_error`。迁移后：
- LLMCallStep.execute 的 except 分支：`_handle_llm_error` + `_afire_hooks("on_error")`
- 骨架删除 L1169

### 难点 4：`after_run` 双路径

`after_run` 有 2 处调用点：
- **no_progress 早返回**（L1244）——不经过 FinalizationStep，**保留骨架**
- **正常结束**（L1251）——迁移到 FinalizationStep

## 实现细节

### DefaultLLMCallStep

```python
async def execute(self, ctx, *, async_mode):
    loop = self._loop
    if loop is None:
        return ctx
    # before_iteration hook
    await loop._afire_hooks("before_iteration", ctx.hook_ctx)
    try:
        response = await loop._get_response(
            ctx.messages, ctx.iteration, async_mode,
            ctx.hook_ctx or loop._build_hook_context(ctx.iteration, ctx.messages),
            ctx.result,
        )
    except Exception as exc:
        loop._handle_llm_error(exc, ctx.iteration, ctx.result)
        await loop._afire_hooks("on_error", ctx.hook_ctx, exc)
        ctx.should_stop = True
        ctx.stop_reason = "error"
        return ctx
    if response is None:
        ctx.should_stop = True
        ctx.stop_reason = "llm_none"
        return ctx
    ctx.response = response
    ctx.response_was_tool_call = bool(getattr(response, "tool_calls", None))
    ctx.response_content = getattr(response, "content", "") or ""
    loop._append_assistant_msg(response, ctx.messages, ctx.result, ctx.iteration)
    return ctx
```

### DefaultFinalizationStep

```python
async def execute(self, ctx, *, async_mode):
    loop = self._loop
    if loop is None:
        return ctx
    loop._finalize_metrics(ctx.result, ctx.messages, ctx.t0)
    loop._run_claim_validation(ctx.result, ctx.messages)
    await loop._afire_hooks("after_run", ctx.hook_ctx, ctx.result)
    return ctx
```

### 骨架收敛

- 删除骨架 `before_iteration`（L1152）
- 删除骨架 `on_error`（L1169）
- 删除骨架正常结束的 `after_run`（L1251）
- **保留** no_progress 早返回的 `after_run`（L1244）
- **保留** 循环级 `after_iteration`（多路径）

## 风险

| 风险 | 缓解 |
|------|------|
| `_get_response` await 后 LLMError 处理差异 | LLMCallStep except 捕获所有异常（含 LLMError），与 legacy `_handle_llm_error` 等价 |
| hook 顺序破坏 | before_iteration 在调用前、on_error 在 handle 后、after_run 在 metrics 后——严格映射 |
| after_run 双路径丢失 | no_progress 早返回保留骨架；正常结束迁入 Step |
| `_call_step` 兜底误吞 LLMError | LLMCallStep 内部精确 except（先于 _call_step），不会到兜底 |
